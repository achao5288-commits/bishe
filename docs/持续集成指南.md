# 持续集成指南

工作流位于 `.github/workflows/ci.yml`。向 `main` 推送、创建或更新 Pull Request，或在 GitHub Actions 页面手动运行时触发。打开仓库的 **Actions → CI** 可查看每次运行及失败步骤；仓库需允许 GitHub Actions，具体可用额度和权限以 GitHub 账户设置为准。

## 检查范围

1. 在 GitHub 托管的临时环境启动 Neo4j 和 Redis，使用 Java 21 执行后端 Maven 测试及打包；关系数据库测试仍使用 H2 的 MySQL 兼容模式，Redis 集成测试使用临时 Redis。
2. 执行 JavaScript 推荐评估工具及冒烟脚本测试、Python 采集工具单元测试，并使用锁文件构建前端。
3. 独立构建完整 Compose 服务，启用 Redis，等待容器就绪后经 Nginx 检查前端页面、景点、图谱、推荐以及账号注册和收藏读取。此步骤使用临时 MySQL 和 Neo4j 数据卷；完成或失败后清理该临时环境。

工作流中的账号、密码和 JWT 字符串仅用于隔离的临时测试实例，不能用于实际部署。工作流不使用真实用户数据、真实模型密钥，也不调用 DeepSeek。Compose 冒烟测试会创建随机测试账号、写入一条收藏，因此只应对临时测试系统运行，不要指向真实用户的环境。

冒烟测试验证关键链路可用，并不代表性能、安全性或推荐效果已经得到全面验证；Redis 单独进行读写与失效测试，Compose 的冒烟链路不能单独证明每种缓存命中情形。GitHub Actions 不会自动部署，也不会默认保护分支；如需强制通过检查才能合并，需要在仓库设置中配置分支保护规则。

## 本地运行

无需 Docker 即可运行脚本测试：

```sh
node --test tools/ci/smoke.test.mjs tools/evaluation/*.test.cjs
```

有独立的临时 Compose 环境时，可按部署指南启用 Redis、启动服务，然后从仓库根目录执行 `node tools/ci/smoke.mjs http://127.0.0.1:8080`。这会创建测试账号和收藏，仅限可丢弃的测试数据库。

如工作流失败，先打开失败步骤的日志，检查依赖下载、服务健康状态和测试断言。完整容器任务失败时会输出服务状态及末尾日志；这些日志可能含环境信息，分享前应检查。请勿将实际密码写入工作流或提交到仓库。
