# 陕北红色文旅智能推荐系统

Vue 3 + Spring Boot + MySQL + Neo4j 的毕业设计项目，支持可选 Redis 缓存。当前收录延安市和榆林市的十六处红色景点，包括凤凰山、瓦窑堡、吴起、杨家沟、小河和神泉堡等。每条景点资料和图谱关系均提供公开来源；图片是 AI 生成的主题插画，不是实景照片。开放时间、票价等动态信息请以景区官方发布为准。

## 已实现

- 按地区浏览景点，结合主题和用户选择的人物、事件、著作或文化主题进行图谱推荐。
- 景点、地区、历史事件、人物、著作和主题实体及其关系存储在 Neo4j；提供可拖动、缩放、点击和按类别筛选的关系图，也提供键盘可操作的清单。
- 每个景点单独配有插画和分段历史故事；每个故事段落附有资料来源。
- 智能问答基于已整理的故事和 Neo4j 关系检索，并使用 DeepSeek 模型生成回答；展示检索来源。
- 景点和推荐结果支持 1–5 分及文字反馈；用户可自愿开启推荐展示记录。
- 可选 Redis 缓存景点列表、图谱和推荐结果，支持管理员刷新与缓存异常回退。

已支持账号注册登录、普通用户及管理员角色；登录后的收藏、浏览、展示记录和评分保存在 MySQL。未登录时收藏与浏览仍保存在当前浏览器。本机旧记录不会自动并入账号；尚未实现路线规划和景点内容后台。目前榆林收录杨家沟、小河、神泉堡、绥德县革命历史纪念馆和郝家桥五处地点，覆盖范围仍可继续扩展。

## 基于知识图谱的推荐

用户可选择地区、景点类型，以及最多 10 项人物、事件、著作或主题；也可从图谱添加兴趣。地区是硬筛选，景点类型匹配加 20 分。对每个不同兴趣，Neo4j 查找景点出发的有向一跳或两跳路径；一跳关系的基础权重分别为：关联事件 60、关联人物 50、关联著作 45、参与事件 45、属于主题 40。两跳路径取各关系权重的最小值后减半（向上取整），取同一景点与兴趣之间得分最高的路径，每个兴趣只计一次；所有兴趣得分与类型分相加，形成基础相关性分。后续通过去重和多样性重排生成最终顺序。

例如：同时选择洛川会议与毛泽东，洛川会议纪念馆的两条直接关系分别贡献 60 和 50 分。接口返回每条路径的关系类型、分值和来源链接，页面展示实际命中的所有兴趣。权重是人工设定的演示参数，并未通过用户实验调优；用户主动选择只用于当前请求。收藏和浏览记录在本机生成兴趣画像，可在页面关闭、清除；启用画像时，推荐请求会向本项目后端发送推导的兴趣 ID、权重及收藏、浏览景点编号。

推荐接口 `POST /api/recommendations` 示例：

```json
{"region":"延安","themes":["纪念馆"],"interestIds":["event-luochuan","person-mao"],"limit":5}
```

返回的 `score` 是基础相关性分，`rerankScore` 是当前位置的重排分；`graphMatches` 中的 `relationTypes`、`points`、`path` 与 `sources` 说明每条命中和来源。当前图谱接口最多返回 500 条关系；大规模数据需要分页或按子图查询。

### Redis 缓存

Redis 为可选组件，默认关闭，不配置时仍直接查询 Neo4j。用户换到配置了 Redis 的电脑后，在启动后端的环境中设置 `REDIS_CACHE_ENABLED=true`；连接参数为 `REDIS_HOST`、`REDIS_PORT` 和可选的 `REDIS_PASSWORD`，默认地址为 127.0.0.1:6379。本仓库 Compose 含仅绑定本机的 Redis 开发服务，未设置 Redis 密码；正式环境需设置访问控制、网络隔离和安全传输，不能使用该开发配置直接公开服务。

缓存采用 cache-aside：景点列表按地区缓存（默认 10 分钟）、全图及景点图谱缓存（默认 10 分钟）、推荐结果按完整请求参数缓存（默认 1 分钟）。TTL 可分别用 `REDIS_ATTRACTION_TTL`、`REDIS_GRAPH_TTL`、`REDIS_RECOMMENDATION_TTL` 配置，使用 `PT10M`、`PT1M` 等 ISO-8601 时长；非正值会绕过缓存。当前“景点缓存”覆盖经常访问的景点列表，并未实现按浏览量计算的热门景点排行榜。

推荐缓存键包含完整请求参数的 SHA-256 摘要，包括兴趣、画像、收藏和浏览编号；不同请求不会共用错误结果，账号令牌不进入缓存键或值。**摘要不等于保密**：推荐结果本身可能反映兴趣，需保护 Redis 的访问权限。收藏或浏览变化后前端发送的新参数会形成新缓存键；缓存不会存储账户资料、评分或认证信息。

应用启动会生成新的本进程缓存命名空间，旧缓存按 TTL 过期；管理员可在“管理用户权限”中点击“刷新景点、图谱和推荐缓存”，或调用需要管理员 JWT 的 `POST /api/admin/cache/invalidate`。修改种子并重启或直接修改 Neo4j 后，应重启服务或手动刷新缓存；未刷新时图谱或景点旧值最多可能保留图谱 TTL，推荐的 1 分钟 TTL 不能单独保证源数据新鲜。刷新切换命名空间，不执行 Redis 全库删除；刷新期间已开始的请求可能返回旧结果，但之后的新请求不会读取旧命名空间。当前刷新和热点锁均为**单进程范围**，多实例部署需为每个实例刷新或实现共享版本及分布式协调。

Redis 连接或读写失败会回退到原始查询，并短暂暂停缓存访问后重试；同一进程对同一热点缓存键的并发回源使用分段锁合并，不能替代多实例防击穿方案。不存在的景点及查询异常不缓存。

本机未配置 Redis，自动测试使用模拟 Redis 验证命中、隔离、刷新、并发和回退，**不能视为真实 Redis 联通测试**。换电脑启动 Redis、MySQL 和 Neo4j 后，可在启动后端之前设置连接参数及 `REDIS_CACHE_ENABLED=true`；要运行真实 Redis 冒烟测试，可在后端测试环境设置 `REDIS_INTEGRATION=true` 后执行：

```sh
cd backend
mvn -Dtest=RealRedisIntegrationTest test
```

该测试只写入有 5 秒 TTL 的独立测试键，不执行 FLUSHDB；默认未配置环境变量时测试跳过。

### 离线评估与局限

启动后端和 Neo4j 后，在项目根目录运行：

```sh
node --test tools/evaluation/evaluate.test.cjs
node tools/evaluation/evaluate.cjs
```

可在第二条命令末尾传入后端地址。脚本读取 `tools/evaluation/cases.json` 中 9 个人工构造场景及分级相关性标注（0–3，未标注为 0），计算 Precision@3、Recall@3 和 NDCG@3 的逐场景与平均值。基线使用同一候选集合和图谱匹配路径，重现原先一跳 60、两跳 30、类型 20 的规则；加权方法按接口返回的基础 `score` 复原重排前排序。两个方法的候选、筛选和排序平局规则一致。为防止截断造成不公平对比，单地区候选超过接口上限 20 时脚本会停止，需先实现分页。

在当前种子数据和示例标注上，基线 P@3=0.5926、R@3=1.0000、NDCG@3=0.9816；加权方法分别为 0.5926、1.0000、1.0000。**这些是开发者构造的小样本演示结果，部分判断反映设计假设，并非真实用户研究或模型泛化效果。**实际论文结论应另行收集独立用户评分，划分独立的调参和测试数据，并报告样本量、评测过程及结果。

### 收藏、浏览和画像推荐

景点卡片可收藏或取消收藏；成功打开景点故事或景点图谱记为一次浏览，重复浏览同一景点只更新最近顺序。收藏最多 100 条、历史最多 50 条；登录后按账号存入 MySQL，可跨浏览器登录访问，未登录时保存在当前浏览器 localStorage；两者各自保留且不会自动合并。画像只使用图谱中景点到事件、人物及主题的一跳边；每处收藏贡献 2、浏览贡献 1，同一景点同时收藏和浏览可合并，重复边去重，各兴趣权重封顶 3，按权重及 ID 稳定排序，最多使用 10 项。

推荐时可以关闭画像；启用时，画像兴趣 ID 和权重（1–3）发送到本项目后端的 `profileInterests` 字段，收藏和浏览景点编号分别通过 `favoriteIds`、`historyIds` 发送用于重排。关闭画像开关时这三项均为空。画像每条路径贡献为图谱路径分 × 兴趣权重 ÷ 10，向下取整；与用户当次手选相同的兴趣只按手选计算。基础分为手选图谱分、类型分和画像分之和，页面展示相关路径和来源。画像根据当前账号记录或本机访客记录推导，这是规则式偏好推导，不是训练模型。

### 去重和多样性重排

在计算基础相关性分之后，采用逐项贪心重排。已收藏的景点减 50 分，已浏览但未收藏的减 30 分；同一景点同时在两份列表中只计算收藏的 50 分。每选出一项，下一个候选根据其与已选结果的类型和地区重复次数分别减分：相同类型每项 8 分、相同地区每项 3 分，每项计数最多按 2 次计算。选择重排分最高的景点；有有效兴趣或行为画像时，平分项根据去重、排序后的兴趣和行为计算稳定散列，同散列再按景点 ID 排序，无画像时按景点 ID 排序。仅在平分时分散，不改变相关性分数，重复直到达到数量限制。地区硬筛选仍然有效，只选择一个地区时地区扣分对候选的相对排序不起作用。

接口返回基础 `score`、`repeatPenalty`、`diversityPenalty` 和该景点被选中当时的 `rerankScore`。后两项随已选结果变化，因此不同位置的重排分不能当作同一时点的全局分数。相同画像与筛选条件的排序可复现；完全相同画像以及无画像用户不会因此被分散。重复景点不会被硬性删除，高相关性可能抵消扣分；关闭画像开关会同时停止上传收藏和浏览编号及相应去重，类型与地区多样性仍生效。所有参数均为未经调优的演示规则。

### 画像推荐的留出评估

`node tools/evaluation/evaluate-profile.mjs` 从 `tools/evaluation/profile-cases.json` 中读取人工构造的收藏和浏览历史，使用与前端相同的画像构造函数；另列出的目标景点作为留出相关性标签，不进入画像。脚本对比相同候选集合、相同空白手选条件下的无画像、重排前画像、重排后画像推荐。前两者按基础分复原旧排序，最后一组发送相同的画像及历史编号并使用接口重排结果。输出逐场景 Precision@3、Recall@3、NDCG@3、类型及地区多样性（前 3 项不同类别数 / 3）、推荐覆盖率（所有场景前 3 项不同景点数 / 候选景点数）和历史景点重复曝光比例。

当前 5 个人工场景中，重排前画像 / 重排后画像结果分别为：P@3 0.2667 / 0.3333、R@3 0.8000 / 1.0000、NDCG@3 0.5047 / 0.8000、覆盖率 0.4375 / 0.6250、重复曝光比例 0.3333 / 0.0000、类型多样性 0.5333 / 0.8000、地区多样性均为 0.6667。**这些场景由开发者构造，与图谱和规则存在设计关联，样本量很小，不证明真实用户收益。**真实实验需要独立参与者、时间顺序的行为切分及未参与调参的测试集；应同时考察推荐准确性和重复曝光。

### 模拟用户基础数据与推荐测试

为便于演示，提供 12 位**虚构**用户的兴趣场景、收藏和浏览历史；对 16 处景点构造共 192 条模拟评分。这些不是用户调查，也不会写入真实反馈数据库。场景与手工设定的评分保存在 `tools/evaluation/synthetic-users.json`，未单独设置的景点统一给模拟 3 分，完整评分矩阵由脚本生成到 `tools/evaluation/synthetic-ratings.json`。

启动 Neo4j 和后端后，运行：

```sh
node --test tools/evaluation/synthetic.test.cjs
node tools/evaluation/run-synthetic.mjs
```

后者实际请求当前推荐接口，使用相同用户画像和候选集合：同时展示仅按基础分、上版去重多样性重排和本版平分分散重排。上版结果固定在 `tools/evaluation/coverage-baseline.json`（对应提交 f455617）；脚本核对模拟场景、图谱种子、运行中图谱和候选景点的指纹，一旦不同则拒绝比较。模拟评分 4–5 分视为正面标签，用户已收藏或浏览的景点不计入留出正面目标，但保留在推荐列表中，以检测重复曝光。运行后会更新 `tools/evaluation/synthetic-report.json` 和完整模拟评分矩阵，模拟结果和每位模拟用户的推荐列表保存在报告文件中；此报告为生成时的快照，修改算法或景点后须重跑。

当前 12 个模拟场景中，上版重排 / 本版重排：Precision@3 为 0.2500 / 0.2778，Recall@3 为 0.4028 / 0.4444，NDCG@3 为 0.2959 / 0.3888；重复曝光比例均为 0，类型多样性均为 0.8333，地区多样性均为 0.6667，景点覆盖率为 0.5625 / 0.6875。该覆盖率仍低于仅按基础分排序的 0.8125，说明取舍仍未完全消除。这些成绩依赖人为场景、默认评分和已选权重，仅能检验实现和展示过程，不代表真实用户满意度或统计显著的改进。

### 真实评分和推荐反馈

景点卡片与推荐结果均可提交 1–5 分和最多 500 字的选填反馈。评分提交即保存到服务端，页面提示不要输入敏感个人信息。同一浏览器对同一景点、同一次展示重复提交会更新该评分；普通景点卡片评分也可更新，但不计入推荐位置的评估。

“同意保存每次推荐的景点列表”默认关闭，只在登录用户开启后记录推荐结果的有序景点 ID、服务端时间和账号 ID；不记录问题、画像、收藏、IP 或浏览历史。用户可随时关闭展示记录；评分是单独主动提交的。推荐结果评分仅在该次展示成功记录后关联到该展示。评分及展示记录归属从服务端验证的登录令牌取得，不信任请求体的用户 ID；页面可删除当前账号的评分和展示记录。

可通过 `GET /api/evaluation/summary` 查询：参与浏览器数、评分数、已同意记录的推荐次数、已评分推荐位置数、全部评分的平均分，以及已评分推荐位置的好评率（4–5 分视为好评）。分母仅包含关联到推荐展示且实际评分的景点，未评分位置不计为差评；空数据时均值和好评率显示暂无数据。统计按展示位置计数，同一人参与多次可能重复贡献，自愿提交会产生选择偏差，不能据此推断总体准确率、因果效果或 A/B 优劣；如需比较算法，应设计有参与者授权的分组实验。

新反馈及展示记录保存在 MySQL 中，汇总接口仅管理员可访问且不返回反馈文字。旧版 `backend/data/evaluation.json` 仍保留，但匿名记录无法安全自动归属新账号，不会自动导入或删除。真实反馈不预置模拟数据。原型尚无登录限流、令牌主动撤销、密码重置与完整审计；公开部署前还需 HTTPS、凭据管理、数据库备份与访问控制等措施。

### 账号与权限配置

用户可在前台注册并登录，用户名为 3–32 位字母、数字或下划线，密码至少 8 个字符且 UTF-8 编码不超过 72 字节。密码使用 BCrypt 哈希保存。后端通过 Spring Security 验证 8 小时有效的 JWT，前端将令牌保存在当前标签页的 sessionStorage；退出登录会删除本页令牌，但已签发令牌本身在到期前不会被服务端主动撤销。浏览景点、推荐和问答无需登录；收藏与历史登录后写入 MySQL，评分及展示记录须登录。账号数据按令牌身份隔离，客户端提交的用户 ID 不参与授权。

初次启动时可通过环境变量 `APP_ADMIN_USERNAME`、`APP_ADMIN_PASSWORD` 配置初始管理员；不提供则不会自动创建管理员。管理员可查看用户列表并调整其他用户角色，不能撤销自己的权限，也不能将当前配置的初始管理员降为普通用户。每次受保护请求都会从数据库读取当前角色，权限变更立即生效；管理员评估汇总接口为 `GET /api/evaluation/summary`，普通用户不能访问，前台不展示测试数据。

使用至少 32 字节随机值设置 `APP_JWT_SECRET`，不要提交到仓库。未设置时服务会生成临时随机密钥，重启后已有令牌失效；多实例或需要重启后保留登录时必须使用相同的安全密钥。初始管理员环境变量仅在该用户名不存在时创建账号，不会覆盖已有密码或提升同名普通账号。生产环境还需 HTTPS、登录限流、令牌撤销、密码重置、审计和数据库安全配置。

MySQL 建表脚本为 `backend/src/main/resources/schema.sql`，应用启动时创建缺失的表，不会自动迁移或覆盖旧文件。生产升级应使用有版本管理的数据库迁移方案并先备份。

## 大模型问答

问答使用 DeepSeek 官方 API 的 `deepseek-flash`，关闭思考模式以控制响应时间和输出。**DeepSeek API 按 token 计费，不保证免费**；赠送额度与余额以账户实际情况为准，价格请查看 [DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing/)。项目不包含密钥；密钥只能保存在服务器环境变量，不要提交到仓库或发给他人。

在启动后端的 PowerShell 终端中设置（输入时不回显），然后运行 `mvn spring-boot:run`：

```powershell
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host '输入 DeepSeek API 密钥' -AsSecureString)).Password
mvn spring-boot:run
```

未配置密钥时，问答明确返回不可用，景点阅读和图谱仍可使用。`POST /api/chat` 请求示例：

```json
{"question":"请讲讲杨家岭的完整故事", "attractionId":1}
```

`attractionId` 可省略，系统会按景点名称、数据中的常用简称或图谱人物/事件名称匹配，最多处理三个景点；未匹配、范围过宽或询问未核实的开放时间、票价等实时信息时，直接说明资料不足，不调用大模型。后台把已整理的故事段落及相关图谱关系发送给模型，并给检索来源编号；服务器仅接受与本次检索来源匹配的方括号编号，无法匹配的编号会标记为未核实。来源是回答所使用的资料集合，编号有效也不代表所引来源一定支持该句，不等于对每句话逐一校验；模型仍可能出错，重要历史事实应核查原始来源。当前故事是已核验资料的分段梳理，无法保证囊括所有史料。

问题和检索资料会发送到 DeepSeek，请勿输入敏感个人信息。每次请求独立，不传入先前聊天记录；页面记录仅保存在当前页面内。示例及测试不包含真实密钥；网关单元测试使用模拟响应，不代表真实服务已连通。

## 历史故事维护

每处景点的背景故事保存在 `backend/src/main/resources/attraction-stories.json`，通过 `GET /api/attractions/{id}/story` 返回。故事按背景、关键经过和后续历史或阅读线索分段，每段保存对应来源名称与链接；正文为依据资料整理的叙述，不是原文全文。现有故事覆盖十二处已收录景点，但历史材料仍可继续扩充，研究时应查看所列来源。

新增或修改景点时，应同步添加同 ID 的故事，核查时间、人物、事件与每段来源。`StoryCoverageTest` 检查景点和故事 ID 一一对应，以及每段标题、正文和 HTTPS 来源非空；该自动检查不能代替历史事实的人工核验。修改 JSON 后重启后端加载。

## 资料采集与人工审核

搜狐攻略文章可作为人工发现景点的线索，但该站点的 robots.txt 对本项目采集程序禁止抓取该文章，实际检查记录见 `data/collection-check.json`。攻略含 AI 生成内容；票价、预约、交通等信息未经核验，不纳入项目数据。新增景点和关系由人工通过官方或公共机构资料核对后录入，不自动同步到图谱。

采集工具 `tools/crawler/collector.py` 可处理用户指定的 HTTPS 页面。它先检查各站 robots.txt；禁止访问或规则不可取得时停止对应页面，不跟随重定向，仅记录标题及词表中命中的景点名称，不保存文章全文，也不自动修改 Neo4j。默认间隔两秒；只访问给定 URL，不发现或批量遍历链接。示例：

```bash
python tools/crawler/collector.py https://example.org/article --terms tools/crawler/terms.json --output data/candidates.json
python -m unittest discover -s tools/crawler/tests -v
```

运行测试前可设置 `PYTHONPATH=tools/crawler`；Windows PowerShell 使用 `$env:PYTHONPATH="tools/crawler"`。对待审核结果进行来源核实、图片版权检查和人工编辑后，才可更新种子数据。采集工具仅用于明确允许抓取的页面，不能绕过站点权限或反爬限制。

## 本地启动

需要 Java 21、Maven 3.9+、Node.js 20+、MySQL 8.4 和 Neo4j 5.26，可选 Redis 7.4。先准备 MySQL 数据库 `red_tourism` 及专用账户 `red_tourism`，设置 `BISHE_MYSQL_PASSWORD`；也可以通过环境变量 `MYSQL_URL`、`MYSQL_USER` 自定义连接。请先启动 Neo4j 并创建本地开发用户 `neo4j`，示例密码为 `local-dev-password`。Docker Compose 启动前须设置 `BISHE_MYSQL_ROOT_PASSWORD` 和 `BISHE_MYSQL_PASSWORD`，两者不应提交到仓库：

```bash
docker compose up -d
```

Compose 的 MySQL 和 Neo4j 端口只绑定本机。已有数据卷首次创建后，修改环境变量不会自动修改数据库账户密码，应在相应数据库中更改。自定义连接通过 `NEO4J_URI`、`NEO4J_USER`、`NEO4J_PASSWORD` 环境变量配置，默认分别为 `bolt://localhost:7687`、`neo4j` 和 `local-dev-password`。确保数据库已启动、账号密码正确且有创建约束及写入权限。应用启动时直接连接并初始化图谱，数据库不可用时应用启动失败。

```bash
cd backend
mvn test
mvn spring-boot:run
```

测试使用 H2 的 MySQL 兼容模式验证关系数据，并连接及写入上述配置的 Neo4j；建议专门使用本地测试图数据库，不要指向生产数据。真实 MySQL 8.4 另需做联通测试。后端默认在 `http://localhost:8081`。

另开一个终端：

```bash
cd frontend
npm install
npm run dev
```

打开 Vite 输出的地址；开发服务器把 `/api` 代理至 `http://localhost:8081`。图谱接口示例：`GET /api/graph` 查询最多 500 条关系，`GET /api/graph/attractions/1` 查询该景点向外最多两跳的关联。景点不存在时返回 404。
